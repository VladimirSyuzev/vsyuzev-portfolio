# Правила перевода (RU → EN)

Свод правил, накопленных по ходу перевода кейсов и главной страницы —
проверяй по этому списку каждый новый переводимый блок и уже переведённые
(этот файл писался по факту найденных багов, не заранее).

## 1. Верстка блока — по авто-лэйауту Figma, не по фикс-координатам

Если в Figma заголовок + один/несколько абзацев текста лежат друг под
другом в одном авто-лэйауте (vertical stack) — в коде это ОБЯЗАН быть
**один flex-col контейнер с одной точкой позиционирования** (`xl:absolute`
на обёртке) и `gap` между детьми, взятым из фактического зазора авто-
лэйаута в Figma для ЭТОГО конкретного блока.

**Никогда** не переносить такой стек как несколько элементов, каждый со
своим независимым фикс `xl:top-[Npx]` — даже если на десктопе это выглядит
1:1 с макетом на русском тексте. Проблема: у EN (или любого другого
языка) текст другой длины → другое число строк → фактическая высота
предыдущего блока меняется → следующий элемент с фикс-`top` либо
наезжает на предыдущий, либо отрывается от него слишком большим
промежутком.

**Симптом бага** (уже дважды находили в этой сессии):
- «О себе» на главной (`src/components/About.tsx`, ≥1440): 2 абзаца био
  сидели на `xl:top-[181px]` / `xl:top-[238px]` независимо — на EN
  (текст короче) между абзацами вылезал большой лишний отступ.
- «Сначала 16px» (`case-02/sections/First16px.tsx`, ≥1440): 2 абзаца
  интро на `xl:top-[181px]` / `xl:top-[221px]` — та же природа бага.

**Фикс** — единая обёртка:
```tsx
<div className="xl:absolute xl:left-[46px] xl:top-[181px] xl:flex xl:w-[668px] xl:flex-col xl:gap-[Npx]">
  <p>{para1}</p>
  <p>{para2}</p>
</div>
```
где `N` — фактический зазор между абзацами В ЭТОМ БЛОКЕ по Figma (не
универсальная константа — см. п.2).

Это **не относится** к элементам, которые в Figma специально стоят
РЯДОМ (разные `left`, одна `top` — колонки) или в РАЗНЫХ несвязанных
местах макета (например, `case-02/VisualLanguage.tsx`: два абзаца на
`left-44/top-181` и `left-726/top-866` — это два независимых текстовых
блока в разных углах секции, не стек, фикс-координаты тут корректны).

## 2. Конкретные проверенные gap-значения (не универсальны!)

Значения зазора отличаются от блока к блоку — **всегда сверяй с Figma**,
не копируй бездумно. Уже подтверждённые:

- Главная, блок «О себе» (`About.tsx`) — где ЗАГОЛОВОК и АБЗАЦ(Ы) БИО
  идут одним стеком: **12px** между заголовком и первым абзацем, **6px**
  между абзацами био. Действует на ВСЕХ брейкпоинтах этого блока (уже
  так было закодировано на sm/lg через `flex-col gap-[6px]` — только
  xl-ветка была багованной фикс-координатой).
- «Сначала 16px» (case-02, `First16px.tsx`) — между двумя абзацами
  интро: **40px** на xl (`Figma 2622:4702`), **6px** на reflow
  (834/1280). Разные брейкпоинты этого ЖЕ блока — разный gap, это
  нормально, так в самой Figma.

Итог: правило про «12 между заголовком и текстом, 6 между абзацами» —
это специфика блока «О себе»/About-паттерна (heading + био), а НЕ
общий закон для любой пары абзацев на сайте. Для каждого нового блока
gap нужно смотреть в Figma отдельно, но **структурно** (см. п.1) всегда
делать через общий flex+gap, а не через дублирующиеся фикс-offset'ы.

## 3. Ручные переносы строк (`<br>`) — повторяй RU-паттерн, проверяй в браузере

- Там, где RU-текст в макете использует ручной перенос строки
  (`<br>` вместо естественного wrap), EN-версия должна ТОЖЕ получить
  свой ручной перенос в том же самом месте по смыслу (тот же
  breakpoint, та же структурная роль) — а не просто отдаваться на
  волю естественного переноса по ширине блока.
- EN-перенос ставится **на семантически похожей границе** (после
  подлежащего/перед смысловым блоком), а не обязательно в том же
  месте по числу слов — фразы разной длины на разных языках.
- Каждый добавленный перенос **обязательно проверяется в браузере**
  (Playwright) на РЕАЛЬНОМ рендере при ЭТОМ брейкпоинте: если
  принудительный перенос конфликтует с естественным wrap блока и
  создаёт «повисшее» одиночное слово на отдельной строке — перенос
  убирается, оставляем чистый natural wrap (см. пример: цитаты в
  AuditLibrary.tsx/TeamGuide.tsx кейса 1, где форсированный перенос
  создавал сиротское слово — в итоге оставлен только natural wrap).
- Если в RU один и тот же перенос обязателен НА ВСЕХ брейкпоинтах —
  EN получает перенос на всех брейкпоинтах. Если в RU перенос стоит
  только `hidden xl:inline` (то есть только на десктопе) — EN получает
  свой перенос ТОЖЕ только на этом брейкпоинте (см. `TeamGuide.tsx`,
  `Consistency.tsx` кейса 1 — на reflow ширинах перенос вообще не
  задан ни у RU, ни у EN, только на xl).

## 4. Длина строки / ширина блока — сопоставимая, не идентичная

- Ширина текстового блока (контейнера) в EN остаётся ТОЙ ЖЕ, что и в
  RU (тот же `w-[Npx]` / `max-w-[Npx]`), если по итоговому рендеру
  текст нормально помещается и не создаёт кривой перенос.
- Если конкретное слово/фраза в EN длиннее и не помещается в RU-ширину
  без явно уродливого переноса (см. `First16px.tsx`: «silhouette,
  composition» не помещалось в 440/449px, разъехалось на 2 строки) —
  ширину блока для EN можно точечно увеличить (не менять RU), проверив
  итог в браузере на всех целевых брейкпоинтах и убедившись, что EN не
  наезжает на соседние элементы (иконку, фото и т.п.).
- Число строк в EN не обязано совпадать с RU 1:1 — но общий визуальный
  объём блока (примерно та же высота/ширина) должен остаться сопоставим,
  чтобы соседние декоративные элементы (эллипсы-обводки, подчёркивания,
  доодлы), завязанные на размер текстового блока в процентах, не
  выглядели слишком тесными или слишком просторными.

## 5. Декоративные обводки/эллипсы вокруг цитат — % от блока, не фикс-px

Обводка-эллипс/подчёркивание вокруг цитаты всегда завязывается на
фактический размер текстового блока в **процентах** (`h-[X%] w-[Y%]`
от родителя = обёртки цитаты), а не на фикс-px, взятый из Figma для
конкретного (обычно более короткого RU) текста — иначе на другом языке
обводка либо режет текст, либо остаётся мелкой/большой не по размеру.

`DrawIn` по умолчанию рисует обводку с `vector-effect="non-scaling-
stroke"` — толщина линии (`stroke-width` из самого SVG-файла) остаётся
в реальных экранных px независимо от того, насколько растянут/сжат бокс
компонента. Поэтому смело увеличивай `h-[%]/w-[%]` под более длинный
EN-текст — линия не «поплывёт» и не исказится.

Если для конкретного языка/брейкпоинта обводка выглядит хуже natural-
wrap текста без неё (например, на очень узком экране обводка стала
тесной несмотря на подгонку % — см. `case-02/Task.tsx` на 375, где
обводку в итоге убрали совсем) — можно убрать декоративный элемент для
этого конкретного случая, не пытаясь любой ценой сохранить его.

## 6. Общий чек-лист перед коммитом переведённого блока

1. RU не тронут / рендерится байт-в-байт как раньше (сверить скриншотом).
2. EN проверен на ВСЕХ брейкпоинтах блока (375 / 834 / 1280 / 1440),
   каждый — отдельным скриншотом, не только «похоже на глаз».
3. Между любыми двумя текстовыми элементами, идущими друг под другом
   в одном авто-лэйауте Figma — либо естественный flow (`gap`-класс на
   общей обёртке), либо (если абсолют неизбежен) единая точка анкера +
   `gap`, никогда два независимых фикс-`top`.
4. Декоративные элементы (обводки/подчёркивания), завязанные на текст
   — в % от блока цитаты, не в фикс-px.
5. `npx tsc --noEmit -p .`, `npx eslint <файлы>`, `npx next build` —
   чисто.
